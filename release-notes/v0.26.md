# V3DRender 0.26

- No RISC OS memory is claimed or given back inside a GraphicsV call.
  Rob Heaton found that doing so froze his V3DDriver with the Task Manager
  open. The driver's postponed memory work is done from a callback instead.
- Cleaning the GPU's caches waits for a pending L2T flush first, as Linux
  now does (Broadcom erratum GFXH-1897).
- Everything up to 0.25: freed GPU memory kept for reuse, start-up
  breadcrumbs, imported memory that follows pages the OS moves.
