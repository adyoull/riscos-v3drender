# V3DRender 0.13

A native RISC OS driver for the Raspberry Pi 4's GPU (Broadcom V3D 4.2), following Linux's v3d driver. Programs reach it through RISC3D.

This release answers riscos-mesa's four requests from comparing V3DRender with Linux's driver, and makes sure V3DRender refuses to start on machines without a V3D. That matters because RISC3D's single package now carries it to every machine. Tested on a Pi 4 under native RISC OS 5 (kit 15: all passed).

## New

- **Screen memory without cache work:** `DRM_RISCOS_IMPORT_UNCACHED` in `drm_riscos_import_memory.flags` (the word was `pad`) marks imported memory the CPU doesn't cache, such as screen memory and screen banks. V3DRender then skips the cache clean and invalidate it did on every job. At 1080p that was about 131,000 cache-line operations each way per frame. 0.11 and 0.12 refuse the flag with `EINVAL`, so programs can try it and drop it.
- **Big pages, as Linux:** buffers of 64 KB and 1 MB or more get GPU addresses aligned to that size, and V3DRender asks for physical memory aligned the same way. The GPU's MMU then uses 64 KB and 1 MB entries, with fewer TLB misses on big textures and frames. On the Pi, an 8 MB buffer is now entirely in 1 MB entries.
- **GPU time per program:** `DRM_IOCTL_RISCOS_FILE_STATS` returns each queue's finished jobs and their time on the GPU, for the calling program and for everyone, as Linux's fdinfo engine statistics. `*V3DRender` shows the totals.
- **After a hang, only the guilty job fails.** Jobs running on the other queues at the time are run again, as Linux resubmits them. `*V3DReset` still ends everything.
- **Refusing to start where there's no V3D 4.2:** on anything but a Pi 4, 400 or CM4 (checked through the firmware's board revision, before anything else is touched), or where the V3D doesn't answer. Now covered by tests.
- `*V3DRender` also shows how much memory is in 1 MB and 64 KB entries, and how many jobs were run again after resets.
- `V3DRender_Debug` 2 places the next buffer at a given GPU address, for the test kit's replay of a hang dump.

See CHANGELOG.md for the details and for 0.01–0.12.

## Requirements

- A Raspberry Pi 4, Pi 400 or CM4 with RISC OS 5.30 or later.
- RISC3D 0.03 or later. Programs reach the GPU through RISC3D only.
- Rob Heaton's V3DDriver not loaded.

The SWI chunk (&C3D40) and error block (&81D340) are provisional.
