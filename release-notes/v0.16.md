# V3DRender 0.16

A native RISC OS driver for the Raspberry Pi 4's GPU (Broadcom V3D 4.2), following Linux's v3d driver. Programs reach it through RISC3D.

## New in 0.16: allocated numbers

RISC OS Open has allocated V3DRender's SWI chunk and error block.

- **SWIs at &5AFC0** (were the provisional &C3D40): `V3DRender_Info` &5AFC0, `_Open` &5AFC1, `_Close` &5AFC2, `_Ioctl` &5AFC3, `_Reset` &5AFC4, `_Debug` &5AFC5.
- **Errors at &823E00** (were &81D340), in the same order.
- **RISC3D_Register is found by name**, so V3DRender registers with RISC3D 0.05 (its allocated chunk, &5AF80) and with older RISC3Ds.
- The module and command names (`V3DRender`, `*V3DClock`, `*V3DDump`, `*V3DPower`, `*V3DReset`) are reserved for it.
- Nothing changes for programs: they take the ioctl SWI from `RISC3D_Info`.

**Use 0.16 with RISC3D 0.05.** RISC3D 0.05 answers only its new numbers, so V3DRender 0.15 and earlier can't register with it.

Everything else is as 0.15. See CHANGELOG.md, and the 0.15 release for the cache work and 0.13's big pages, GPU time per program and uncached imports.

## Downloads

- `V3DRender-0.16.zip`: the module, with its licence.
- `V3DRenderTest-19.zip`: the test kit, with RISC3D 0.05. Run Check, then read Results.

## Requirements

- A Raspberry Pi 4, Pi 400 or CM4 with RISC OS 5.30 or later.
- RISC3D (0.05 for the allocated numbers). Programs reach the GPU through RISC3D only.
- Rob Heaton's V3DDriver not loaded.
